# rinze

SKK 方式の IME。打ち方は SKK と同じで、変換候補の順位を「直前に使った候補」ではなく、カーソルより前の文章 (左文脈) で決める。
候補は SKK 辞書とユーザー辞書から引き、ニューラルかな漢字変換モデル zenz で各候補の対数尤度を計算して並べ替える。
選び直した候補は覚えて小さく加点するが、文脈がはっきり決める候補は入れ替えない ([学習](#学習))。
辞書の候補を送り切ると zenz が生成した表記を出し、それも送り切ると SKK と同じ辞書登録に入る。

入力モードは SKK と同じく、ひらがな、カタカナ、半角カナ、全角英字、ASCII の 5 つがある。フロントエンドは [Neovim](#neovim) と Linux の [fcitx5](#fcitx5) がある。

## 入れ方

flake から rinzed、zenz のモデル、SKK 辞書、Neovim プラグインを入れる。flake の `rinzed` はモデルと辞書の既定値を持つので、PATH に入れればプラグインは引数なしで起動できる。

### 試す

```sh
nix run /path/to/rinze#demo
```

`--clean` の Neovim に rinze と blink.cmp を設定して起動し、rinze を有効にした状態で挿入モードに入る。`Asita` で blink.cmp のメニューに候補が出て、Space で変換、`C-y` でメニューの候補を確定、`C-l` でオンオフを切り替える。
ソケット、ユーザー辞書、学習の履歴、Neovim と blink.cmp の状態は `/tmp/rinze-demo-*` に置き、終了すると rinzed を止めてディレクトリごと消す。利用者のユーザー辞書、履歴、既定のソケットには触れない。

### flake の出力

| 出力 | 中身 |
| --- | --- |
| `packages.<system>.rinzed` (`default`) | モデルと辞書の既定値を持つ rinzed。`rinzed-unwrapped` のラッパー |
| `packages.<system>.rinzed-unwrapped` | 既定値を持たない rinzed |
| `packages.<system>.rinze-zenz-model` | zenz-v3.2-small の GGUF ([モデルと辞書](#モデルと辞書)) |
| `packages.<system>.rinze-dictionaries` | 既定の SKK 辞書を `share/skk` にまとめたもの |
| `packages.<system>.rinze-nvim` | Neovim プラグイン (`vimUtils.buildVimPlugin`) |
| `packages.<system>.fcitx5-rinze` | fcitx5 のアドオン ([fcitx5](#fcitx5))。Linux だけ |
| `packages.<system>.demo`、`apps.<system>.demo` | 上の試用の入口 |
| `overlays.default` | 上の `rinzed`、`rinzed-unwrapped`、`rinze-zenz-model`、`rinze-nvim` を pkgs に足す |
| `checks.<system>` | rinzed とプラグインのビルド、Lua と Rust の[検査](#検査)、既定のソケットのパスの一致 (Lua 側)、`setup` に何も渡さずに PATH の rinzed を起動して候補を引けること。Linux では fcitx5 のアドオンを testfrontend で打って確かめること ([fcitx5 のテスト](#fcitx5-のテスト)) |

system は `x86_64-linux`、`aarch64-linux`、`aarch64-darwin`。バイナリキャッシュは無いので、rinzed は手元で llama.cpp ごとビルドする。

#### 既定値の渡し方

`rinzed` は `rinzed-unwrapped` を `makeBinaryWrapper` で包み、環境変数 `RINZED_DEFAULT_MODEL` にモデルのパスを、`RINZED_DEFAULT_DICTS` に辞書のパスを `:` 区切りで入れる (`--set-default` なので、起動時の環境にあればそちらを使う)。
rinzed は `--model` を省くと `RINZED_DEFAULT_MODEL` を、`--dict` を 1 つも渡さないと `RINZED_DEFAULT_DICTS` を使う。`--dict` を 1 つでも渡すと既定の辞書は使わない。

既定の辞書を変えるには `override` で `dictionaries` を渡す。辞書のパッケージ (`share/skk` の下の辞書をすべて使う) と辞書のファイルを混ぜて並べられ、並べた順が[複数の辞書](#複数の辞書)の順になる。

```nix
rinzed.override {
  dictionaries = rinzed.dictionaries ++ [ ./skk-jisyo.imas.utf8 ];
  # model = ...;
}
```

### home-manager と lazy.nvim

Neovim の設定を Nix の外 (out-of-store symlink など) に置き、lazy.nvim でプラグインを管理している場合の入れ方。home-manager でプラグインを決まった場所に置き、lazy.nvim の `dir` で読む。
lazy.nvim は既定で runtimepath と packpath を作り直すので、`pack/*/start` に置いたプラグインは読まれない。

```nix
# flake.nix の inputs
rinze.url = "git+file:///path/to/rinze";
```

```nix
# home-manager のモジュール
{ inputs, pkgs, ... }:
let
  rinze = inputs.rinze.packages.${pkgs.stdenv.hostPlatform.system};
in
{
  home.packages = [ rinze.rinzed ];
  xdg.dataFile."nvim/rinze".source = rinze.rinze-nvim;
}
```

```lua
-- lazy.nvim のプラグインの一覧
{
  dir = vim.fn.stdpath("data") .. "/rinze",
  name = "rinze",
  config = function()
    require("rinze").setup({ blink = true })
    vim.keymap.set("i", "<C-l>", function() require("rinze").toggle() end)
  end,
},
```

`inputs.rinze.inputs.nixpkgs.follows` で nixpkgs を揃えると、rinzed をビルドするコンパイラも変わる。[複数の辞書](#複数の辞書)などの測定の数字は rinze の `flake.lock` の nixpkgs で出したもの。nixos-26.05 (`6dadaf43`) に揃えてビルドした rinzed でも、コーパスの全区間の結果は同じだった。

## 構成

| crate | 役割 |
| --- | --- |
| `rinze-engine` | 入力の状態機械。入力モード、ローマ字の解釈、▽ / ▼ の状態、abbrev、候補の送り、見出しの入力中の候補の選択、辞書登録 (入れ子を含む)、辞書から消すかの問いを持つ。入出力を持たず、候補の取得、登録した語の保存と削除、確定した候補の通知は `Converter` trait に任せる |
| `rinze-dict` | SKK 辞書の読み込みと見出しの検索、SKK 辞書のテキストへの語の追加と削除 (`skk-ignore-dic-word` での除外を含む) |
| `rinze-zenz` | zenz による候補の点数づけと、ビーム探索による表記の生成 |
| `rinzed` | 常駐プロセス。システム辞書 (複数を合わせたもの)、ユーザー辞書、学習の履歴、zenz を 1 つずつ持ち、Unix ドメインソケットで msgpack-rpc を受ける。上の 3 つを繋ぐ唯一の場所で、ユーザー辞書と学習の履歴を書くのも rinzed だけ |
| `rinze-socket` | 既定のソケットのパスの規則。rinzed と rinze-client が共有する |
| `rinze-client` | rinzed のクライアント。接続、応答の解釈、rinzed の自動起動、先読み、左文脈から未確定文字列を除く処理を持ち、C ABI で fcitx5 のアドオンから使う ([fcitx5](#fcitx5)) |

フロントエンドは接続ごとに独立した入力状態を持ち、入力モードもその一部として rinzed が持つ。フロントエンドはモードを判断せず、キーを送って応答を表示する。Neovim のプラグインは `nvim/`、fcitx5 のアドオンは `fcitx5/` にある。
入力状態を分けたい場所ごとに接続を分ける。Neovim のプラグインは、挿入モード、[コマンドライン](#コマンドライン)、blink.cmp の問い合わせにそれぞれ別の接続を使う。fcitx5 のアドオンは、入力欄 (fcitx5 の入力コンテキスト) ごとの接続と、先読みの接続を使う。

### 通信

msgpack-rpc の要求を 6 種類受け付ける。

- `key(key, left_context)`: `key` は 1 文字か `space` `enter` `backspace` `ctrl-g` `ctrl-j` `ctrl-q`。`left_context` はカーソルより前の文字列で、zenz にはその末尾 40 字を渡す。
- `flush()`: 入力途中のものを表示どおりに確定し、状態を空にする。入力モードは変えない。
- `discard()`: 入力途中のものを確定せずに捨て、状態を空にする。入力モードは変えず、辞書登録の入力欄にいれば外側のモードに戻る。何も確定しないので[学習](#学習)の履歴にも書かない。fcitx5 のアドオンが、入力欄からフォーカスが外れたときに使う。
- `reset()`: `flush` したうえで、入力モードをひらがなに戻す。フロントエンドが入力を有効にしたときに使う。
- `choose(version, word, left_context)`: 見出しの入力中 (▽) に、その読みの候補 `word` で見出しを確定する。Space で変換して `word` まで送って確定したのと同じに扱い、最初の候補だったかを[学習](#学習)に知らせる。`version` が最後の応答の `version` と違えば (そのあとにキーを処理していれば) 何もせず、`handled` を false で返す。`word` が見出しの候補に無いときも同じ。
- `lookup(reading, left_context)`: 送りがなの無い読み `reading` の候補を、Space で変換したときと同じ順の文字列の配列で返す。入力状態に触れないので、キーを送る接続と別の接続で、キーの処理を待たせずに問い合わせられる。生成した表記は含めない。

`lookup` 以外は次の map を返す。

| キー | 内容 |
| --- | --- |
| `handled` | false ならフロントエンドは `commit` を挿入したあと、元のキーを通常どおり処理する |
| `commit` | 確定した文字列 |
| `preedit` | 未確定文字列 (`▽あし`、`▽あ*t`、`▼明日`、`▽file` など) |
| `candidates` | 候補一覧の表示中だけ `{items = [[選択キー, 候補], ...], page, pages}`、それ以外は nil。辞書登録中は入力欄の変換の一覧 |
| `minibuffer` | 辞書登録の入力欄か、辞書から消すかの問いがあるときだけ、いちばん内側のもの `{prompt, text, preedit}`、それ以外は nil。`prompt` (`[辞書登録] まよねーず: `、入れ子では `[[辞書登録]] まよ: `、消すときは `あした /朝/ を辞書から削除します。良いですか？ (yes or no) `)、`text` (確定した文字列)、`preedit` (未確定文字列) をこの順に並べて表示する |
| `mode` | 次のキーを受ける階層の入力モード。`hiragana` `katakana` `halfwidth-katakana` `ascii` `fullwidth-latin` のどれか。辞書登録中はいちばん内側の入力欄のモード |
| `passthrough` | true の間は `ctrl-j` 以外のキーをすべて処理せずに返す (`handled` は false、`commit` は空) ので、フロントエンドは `ctrl-j` 以外のキーを送らずにそのまま処理してよい。外側が ASCII モードのときだけ true で、辞書登録の入力欄が ASCII モードのときは入力欄に文字を入れるので false |
| `reading` | 見出しの入力中 (▽) だけ、Space で変換する読み (`▽あしt` なら `あし`)。送りがなの入力中、abbrev、辞書登録の入力欄では nil |
| `version` | 接続ごとに、要求を処理するたびに増える数。`choose` に渡す |

辞書登録中も `preedit` は元の位置の未確定文字列 (`▼まよねーず`) で、入れ子の状態はすべて rinzed が持つ。
rinzed は 1 つの接続の要求を受け取った順に 1 つずつ処理し、応答も同じ順に返す。fcitx5 のアドオンは、待ち切れなかった応答を捨てずに、次の要求の前に読む ([rinzed の起動と応答の待ち](#rinzed-の起動と応答の待ち))。
接続を閉じると、rinzed はその接続の入力状態を確定せずに捨てる。入力途中のものは確定せず、学習の履歴にも書かない。入力途中を捨てたいフロントエンドは、入力モードを残すなら `discard` を送り、入力モードも要らなければ `flush` を送らずに接続を閉じる。
rinzed は最後に zenz でつけた点数を 1 組覚えていて、左文脈と読みと候補が同じ問いには点数をつけ直さない。`lookup` で並べた読みをそのまま Space で変換すると、並べ替えを待たない (下の [blink.cmp との連携](#blinkcmp-との連携))。

### 点数づけのスレッド

rinzed は zenz の点数づけを `--threads` (既定は CPU の数で、8 まで) のスレッドで走らせる。点数づけは接続によらず一度に 1 つずつ走る。
Linux では llama.cpp が OpenMP (libgomp) でスレッドを分ける。libgomp の既定では、手の空いたスレッドがほかのスレッドを CPU を回しながら待つので、ほかのプロセスで CPU が詰まっていると待つスレッドが互いの CPU を奪い、点数づけが何十倍も遅くなる。
rinzed は環境変数 `OMP_WAIT_POLICY` が無ければ `PASSIVE` にして自分を実行し直し、待つスレッドを眠らせる。`OMP_WAIT_POLICY` を渡せば、その値を使う。
`stress-ng --cpu 32` で 16 コアを埋めた間に、先読みなしで Space を 8 回打つと、既定の待ち方では中央値 8.6 秒で 1 回は 10 秒を超え、`PASSIVE` では中央値 1.0 秒、最大 1.6 秒だった。
代わりに負荷の無いときは 2 割ほど遅くなり、点数づけの中央値は `か` (候補 94 件) で 31 ms から 39 ms に、`こう` (239 件) で 69 ms から 82 ms になった (12 回ずつ)。どれも 16 コアの x86_64、8 スレッド、L の辞書で測った。

### 常駐メモリ

既定の 5 つに imas と emoji を足した 7 つの辞書で、rinzed の RSS は待ち受けを始めた時点で 123 MB、コーパスを 3 周打ったあとで 135 MB になる (削減の前はそれぞれ 211 MB と 245 MB)。2 周目からは増えない。
内訳は次のとおり。`/proc/<pid>/smaps` の領域ごとの値と、段階ごとに読み込みを止めたプログラムでの `mallinfo2` から割り出した。

| もの | 大きさ | 削減の前 |
| --- | --- | --- |
| モデルのファイルの写し (mmap) | 72 MB | 72 MB |
| 実行ファイルと共有ライブラリ | 7 MB | 7 MB |
| 辞書 7 つ | 19 MB | 97 MB |
| KV キャッシュ (`N_CTX` 512) | 18 MB | 36 MB |
| llama.cpp の計算用の領域、出力、作業用の領域 | 約 15 MB | 約 30 MB |
| モデルの語彙など | 5 MB | 5 MB |

- 辞書は見出しと候補の文字列を 1 つのバッファに詰め、見出しの順に並べた表を二分探索で引く。文字列ごとに `String` と `HashMap` で持っていたときと引いた結果は同じで (7 つの辞書の 30 万見出しすべてで確かめた)、引く速さも同じ (1 見出しあたり約 250 ns)、読み込みは 210 ms から 90 ms になった。
- KV キャッシュは `N_CTX` に比例し、確保した時点で全体が埋まる。点数づけは 1 回の decode にプロンプトと 64 トークンしか置かず、生成のビームは接頭辞を共有するので、512 でも左文脈 40 字のまま 85 字の読みまで生成できる (1024 では 145 字まで確かめた)。256 にすると 9 MB 減るが、生成できる読みが 40 字ほどまでになる。
- 候補の最後のトークンのあとの logits は使わないので、最後のトークンは decode しない。1 文字の候補はプロンプトの logits だけで点数がつく。llama.cpp は出力の領域を 1 回の decode で載せた件数まで広げて縮めないので、1 回に載せるトークンを 64 までにして、出力の領域を最初の 1.5 MB に留める。点数づけは `こう` (241 件) で 255 ms から 88 ms に、`かんじ` (24 件) で 50 ms から 40 ms になった (直接 zenz で、11 回の中央値を交互に 5 組)。
- 点数は候補を decode する組み方で 1 nat ほどまで動く。削減の前のコードでも、候補の順を逆にするだけで 920 問 3512 候補のうち 1492 候補の点数が変わり、5 問で順位が入れ替わった。組み方を変えたあとの差 (7 問で順位が入れ替わり、1 問で 1 位が変わった) も同じ程度で、コーパスの全区間の結果は変わらなかった。
- 接続を増やしても、1 接続あたり約 0.07 MB しか増えない。スレッドは点数づけを頼んだ接続ごとに OpenMP のスレッドが増えるが、スタックはほとんど使われない。

## 打ち方

SKK と同じ。

- 大文字で見出しの入力を始める。送りがなの無い語は Space で変換する。
- 送りがなのある語は、送りがなの開始を大文字で打つと変換が始まる (`AEmasu` は「あ*え」、`ATte` は「あ*っ」)。
- 候補の表示中に Space で次の候補、`x` で前の候補。最初の 4 候補はその場に表示し、5 候補目からは一覧を出して `asdfjkl` で選ぶ。
- 候補の表示中に次の文字を打つか Enter で確定する。`C-g` で取り消す。
- 辞書の候補を送り切ると、zenz が生成した表記を続けて出す。辞書に見出しの無い読みでは生成した表記が最初の候補になる (`Mayone-zu` の Space で「マヨネーズ」)。
- 生成した表記も送り切ると辞書登録に入り、`[辞書登録] まよねーず: ` の入力欄で登録する語を打つ。入力欄でも変換でき、そこで辞書登録に入れば入れ子になる。Enter で登録して元の位置に確定し、空のまま Enter するか `C-g` で登録をやめて元の状態に戻る。送りありの語は送りがなを除いて打つ (打っても除く)。
- 候補の表示中に `X` を打つと、ddskk と同じく表示中の候補を辞書から消すかを問う。`yes` と打って Enter で消し、表示中の候補を確定せずに消す。`no` か `C-g` で候補の表示に戻る。候補の表示中でなければ `X` はそのまま入る。
  - ユーザー辞書だけにある語は、ユーザー辞書の行から除く。
  - システム辞書にある語は、ddskk と同じくユーザー辞書のその見出しの行の先頭に `(skk-ignore-dic-word "明日")` を書き、以後その見出しの候補に出さない。同じ行で消した語は 1 つの `(skk-ignore-dic-word "明日" "朝")` にまとめる。注釈のある語は注釈も含めて ddskk と同じ書き方 (`"晨\073あさ"`) で書く。zenz の生成した表記にも出さない。
  - どちらの辞書にも無い語 (生成した表記) も同じく `skk-ignore-dic-word` に書き、以後その読みで生成しても出さない。
  - 消した語をもう一度辞書登録すると、行の先頭に語を書き、`skk-ignore-dic-word` からも外す。ddskk は `skk-ignore-dic-word` を残したまま語を先頭に足し、その時点では同じく候補に出すが、同じ行で別の語を消すと `skk-ignore-dic-word` を先頭に移すので登録し直した語がまた出なくなる。rinze は外すので、どちらで読んでも登録し直した語が出る。
  - その候補の[学習](#学習)の履歴も消す。
- `Q` で空の見出し (▽) に入る。見出しの途中なら、それまでの見出しをかなで確定してから新しい見出しに入る。空の見出しで Space を打つと見出しをやめる。
- Enter は確定だけを行い、改行しない。ddskk の既定 (`skk-egg-like-newline` が nil) では確定と同時に改行するが、rinze は `skk-egg-like-newline` を t にしたときと同じに動く。

### abbrev

かな系のモードで `/` を打つと、ddskk の abbrev と同じく英字の見出しに入る (`▽file`)。Space で SKK 辞書の英字の見出しを引いて変換する (`/file` の Space で「ファイル」)。

- 英字の見出しには小文字、大文字、記号がそのまま入る (`q` `l` `L` もモードを切り替えない)。
- Enter と `C-j` で英字のまま、`C-q` で全角英字にして確定する。`C-g` でやめる。
- 候補の送り、`x`、確定は、かなの見出しと同じ。確定すると元のかなのモードに戻り、確定に使った文字はかなとして打つ (`/file` の Space のあとの `a` は「ファイルあ」)。
- 候補は辞書の順のまま出し、zenz では並べ替えない。英字をそのまま読みとして zenz に渡すと、綴りに近い表記 (「サーバ」「USER」「テクスト」) が上がり、33 件の測定で 1 位に期待する表記が出たのは辞書の順で 29 件、zenz の順で 23 件だった。`cargo run --release -p rinzed --example abbrev_ranking` で測り直せる。
- zenz は読みをかなで受け取るので、英字の見出しでは表記を生成しない。辞書に無ければそのまま辞書登録 (`[辞書登録] file: `) に入り、登録した語はユーザー辞書の送りなしの節に書く。

### ローマ字

ローマ字の規則は ddskk の `skk-rom-kana-base-rule-list` と `skk-rom-kana-rule-list` の既定値に合わせている。`z` で始まる記号 (`z ` の全角空白、`z*` の「※」、`zL` の「⇒」など) と `mm` の「んm」も ddskk と同じ。次の点だけ ddskk と違う。

- ひらがなモードとカタカナモードでは、`!` は「！」、`~` は「〜」(U+301C) になる。ddskk の既定ではどちらも変換せずにそのまま入るが、日本語の文章では全角で打つことが多いので全角にした。
- 半角カナモードでは、`!` と `~` はそのまま入る。半角カナモードは半角の形がある記号を半角にして出し、「〜」は Emacs の `japanese-hankaku` と同じく `~` にするので、`z-` も `~` になる (ddskk の半角カナモードの `z-` は「〜」)。
- `va` などは「う゛ぁ」ではなく「ゔぁ」、ひらがなモードの `xka` `xke` は「か」「け」ではなく「ゕ」「ゖ」を出す。カタカナモードではどちらも ddskk と同じになる。
- `@` (`skk-today`)、`$` (`skk-display-code-for-char-at-point`)、`\` (`skk-input-by-code-or-menu`) は関数を呼ばず、そのまま入る。

### 入力モード

切り替えのキーと各モードでの振る舞いは ddskk の既定 (`skk-use-jisx0201-input-method` を有効にした状態) に合わせている。

| キー | ひらがな | カタカナ | 半角カナ | 全角英字 | ASCII |
| --- | --- | --- | --- | --- | --- |
| `q` | カタカナへ | ひらがなへ | ひらがなへ | `ｑ` を入力 | `q` を入力 |
| `C-q` | 半角カナへ | 半角カナへ | ひらがなへ | カタカナへ | 通す |
| `l` | ASCII へ | ASCII へ | ASCII へ | `ｌ` を入力 | `l` を入力 |
| `L` | 全角英字へ | 全角英字へ | 全角英字へ | `Ｌ` を入力 | `L` を入力 |
| `C-j` | 入力途中を確定 | 入力途中を確定 | 入力途中を確定 | ひらがなへ | ひらがなへ |

- 見出しの入力中 (▽) の `q` は見出しをカタカナ (カタカナモードではひらがな、半角カナモードでは半角カナ) にして確定し、`C-q` は見出しを半角カナにして確定する。どちらもモードは変えない。`l` `L` は見出しをそのまま確定してから切り替える。
- 候補の表示中 (▼) に切り替えのキーを打つと、表示中の候補を確定してから切り替える。一覧の表示中は `l` も選択キーになる。
- ローマ字の途中で打った `q` `l` `L` は、ローマ字の続きになるとき (`zl` の「→」) はローマ字として扱う。続かないときは保留中の `n` を「ん」にし、ほかの保留は捨ててから切り替える。
- カタカナと半角カナのモードでも、大文字での見出し開始、Space と送りがなでの変換、候補の送り、辞書登録はひらがなモードと同じに動く。辞書の見出しと zenz に渡す読みはどのモードでもひらがなで、未確定文字列、確定する送りがな、変換せずに確定するかなはモードの文字種にする。
- 全角英字は ddskk の `skk-jisx0208-latin-vector` の表で変換する (Space は「　」、`-` は「−」、`~` は「〜」)。
- ASCII モードでは `C-j` 以外のキーを rinze が処理しない。
- 辞書登録の入力欄は外側のモードと別のモードを持ち、ddskk と同じくひらがなで始まる。入力欄の中で切り替えても外側のモードは変わらず、登録を終えるかやめると外側のモードに戻る。

### 生成する表記

zenz に幅 8 のビーム探索で表記を生成させ、次のものを捨てる。

- 最も尤もらしい表記から対数尤度が 6 以上低いもの。これより下は読みと無関係な語が増える。
- 送りありで、送りがなで終わらないもの。
- 読みに対応しないもの。表記の中のかなが読みの同じ位置のかなと一致し、かな以外の連なりが読みの 1 字以上に当たるかで調べる (「天気がよい」は「てんきがいい」に対応しない)。
- 読みと同じひらがなのもの、辞書の候補と重複するもの。

生成には 1 回 27〜112ms かかり、辞書の候補の並べ替え (12〜20ms) より遅いので、辞書の候補を送り切ったときに初めて計算する。辞書に見出しが無いときだけ変換の開始時に計算する。
`cargo run --release -p rinzed --example timing` で読みごとの所要時間と生成した候補を測れる。

### ユーザー辞書

登録した語は SKK 辞書と同じ書式の UTF-8 のテキストに書く。既定の場所は Linux で `$XDG_DATA_HOME/rinze/user.jisyo` (無ければ `~/.local/share/rinze/user.jisyo`)、macOS で `~/Library/Application Support/rinze/user.jisyo` で、`rinzed --user-dict` で変えられる。
書くのは rinzed だけで、一時ファイルに書いて fsync してから rename するので、途中で落ちても壊れない。ユーザー辞書の語はシステム辞書の候補と合わせて zenz で並べ替え、先頭には固定しない。
ユーザー辞書の行の `(skk-ignore-dic-word "語" ...)` に書いた語は、その見出しのシステム辞書の候補と生成した表記から除く。ddskk の書いたユーザー辞書の行も同じに読み、同じ行に `skk-ignore-dic-word` と並べて書かれた語はユーザー辞書の語として出す。

### 学習

候補を送るか一覧から選んで確定した候補 (選び直した候補) と、辞書登録した語を、見出しごとに覚える。
次に同じ見出しを変換するとき、その見出しで最後に選び直した候補 1 つだけに、zenz の点数 (対数尤度の和) へ加点してから並べる。

- 加点は、左文脈があるとき 0.75、左文脈が空 (行頭や、空白だけのとき) のとき 3.0 で、単位は zenz の点数と同じ nat。文脈があれば、zenz がほかの候補を 0.75 より大きく上に置く場合は文脈が勝つ。
- 最初に出た候補をそのまま確定したときは覚えない。zenz が当てた語を覚えても順位は変わらず、別の文脈でその語に引っぱられる原因にだけなる (下の測定)。
- 生成した表記を選んでも覚えない。辞書の候補ではないので、次の変換の候補に無く、加点する先が無い。
- abbrev の候補は zenz で並べ替えないので、最後に選び直した候補を先頭に出し、ほかは辞書の順のまま出す。
- 候補の表示中に `X` で辞書から消すと、その候補の履歴も消す。
- 確定の経路 (次の文字、Enter、`C-j`、モードの切り替え、一覧からの選択、後退、`flush`、`reset`、辞書登録、見出しの入力中の `choose`) はどれも、エンジンの `Converter::committed` を 1 回呼ぶ。`discard` は何も確定しないので呼ばない。最初に出た候補だったかを `Pick` で渡し、覚えるかは rinzed が決める。経路ごとの通知は `cargo test -p rinze-engine` が確かめ、コーパスの全区間で区間ごとに 1 回ずつ通知することも確かめる。

履歴は UTF-8 のテキストで、1 行に `見出し<TAB>候補<TAB>最後に選び直した時刻 (UNIX 時刻のミリ秒)` を書く。
既定の場所は Linux で `$XDG_STATE_HOME/rinze/history.tsv` (無ければ `~/.local/state/rinze/history.tsv`)、macOS で `~/Library/Application Support/rinze/history.tsv` で、`rinzed --history` で変えられる。
`rinzed --no-learning` で学習を止め、履歴を読みも書きもしない。

書くのは rinzed だけで、ユーザー辞書と同じく、ロックを取ってから最新の内容を読み直して記録を足し、一時ファイルに書いて fsync してから rename する。
途中で落ちても壊れず、別のソケットで動く rinzed が同じ履歴を書いても互いの記録を消さない。
選び直した候補を確定したキーの処理の中で書く。確定のキー 1 回の往復は、学習なしの 0.02 ms に対して、空の履歴で中央値 3.3 ms (1.2〜3.6 ms)、5000 行の履歴で 6.2 ms (4.8〜8.1 ms) だった (btrfs on NVMe、それぞれ 50 回)。
空の履歴では fsync 2 回 (ファイルとディレクトリ) が大半で、行が増えると読み直しと書き直しが増える。変換 1 回 (12〜20 ms) より短く、最初の候補の確定 (0.04 ms) は学習なしと変わらないので、書く時機は遅らせていない。

```sh
cargo build --release -p rinzed
tests/nvim/commit_timing.sh      # ROUNDS で回数を、HISTORY_LINES で行の多い履歴の行数を変えられる
```

#### 加点の形と大きさ

`cargo run --release -p rinzed --example learning_eval` で測り直せる。zenz の点数は左文脈と候補だけで決まり、履歴では変わらないので、各場面の点数を 1 度だけ計算し、加点の形と大きさを変えながら履歴を積んだあとの 1 位を数える。
場面は `crates/rinzed/examples/learning_cases.json` にあり、文脈で答えが変わる同音異義語 40 件 (`tests/fixtures/spike_ranking.json` と同じ場面に答えを付けたもの)、人名 9 件、左文脈の無い語 11 件、それと対になる文脈のある語 13 件からなる。人名と左文脈の無い語の答えは、zenz の 1 位でない候補を利用者が選ぶものとして決めた。

- 引っぱられない: 同じ見出しで文脈により答えが変わる組 (A, B) のうち、学習なしで B の文脈の 1 位が B の答えだった 45 組で、A の文脈で A の答えを 20 回確定したあとも B の答えが 1 位である数。「最悪」は、A の答えの確定を毎回覚えた場合 (A の答えが A の文脈でも 1 位でなく、毎回送って選んだ場合) の数。
- 覚える: 学習なしで 1 位が答えでなかった 33 場面 (コーパスの 7 区間を含む) で、同じ文脈で答えを 1 回 (と 3 回) 確定したあと答えが 1 位になる数。
- 選び直しに追従: 答えを覚えさせ、学習なしの 1 位に選び直し、もう一度答えを選んだあと、答えが 1 位になる数。
- コーパス 2 周目: [コーパス](#日常の文章での-1-位正解率) を履歴の空の状態から 1 周打ったあとの 2 周目の 1 位正解率。学習なしは 198/206。

| 覚える確定 | 形 | 加点 | 引っぱられない | 最悪 | 覚える (1 回 / 3 回) | 選び直しに追従 | コーパス 2 周目 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| すべて | 固定 | 0.5 | 43/45 | 43/45 | 8 / 8 | 0/33 | 198/206 |
| すべて | 最新だけ | 0.75 | 43/45 | 43/45 | 11 / 11 | 11/33 | 198/206 |
| 送ったときだけ | 固定 | 0.75 | 45/45 | 43/45 | 11 / 11 | 0/33 | 198/206 |
| 送ったときだけ | 回数で飽和 | 1.5 | 45/45 | 42/45 | 11 / 17 | 9/33 | 198/206 |
| 送ったときだけ | 回数で飽和 | 3 | 44/45 | 37/45 | 21 / 29 | 16/33 | 199/206 |
| 送ったときだけ | 新しさで半減 | 0.75 | 45/45 | 43/45 | 11 / 11 | 5/33 | 198/206 |
| 送ったときだけ | 最新だけ | 0.75 | 45/45 | 43/45 | 11 / 11 | 11/33 | 198/206 |
| 送ったときだけ | 最新だけ | 1 | 44/45 | 42/45 | 15 / 15 | 15/33 | 199/206 |
| 送ったときだけ | 最新だけ | 2 | 44/45 | 42/45 | 25 / 25 | 25/33 | 200/206 |
| 送ったときだけ | 最新だけ | 0.75、文脈なし 1.5 | 45/45 | 43/45 | 18 / 18 | 18/33 | 198/206 |
| **送ったときだけ** | **最新だけ** | **0.75、文脈なし 3** | **45/45** | **43/45** | **24 / 24** | **24/33** | **198/206** |
| 送ったときだけ | 最新だけ | 0.75、文脈なし 100 | 45/45 | 43/45 | 25 / 25 | 25/33 | 199/206 |

形は、固定 (選んだことがあれば加点)、回数で飽和 (`加点 × (1 − 2^−回数)`)、新しさで半減 (新しい順に 1、1/2、1/4 倍)、最新だけ (最後に選び直した候補だけ) を比べた。

- 覚える確定を、送ったときだけにした。すべての確定を覚えると、加点 0.5 から 45 組のうち 2 組 (「卵が」の孵と帰、「入会を」の勧と進。点差はどちらも 0.3) が、A の文脈で 1 位の語を確定しただけで崩れる。
- 形は最新だけにした。引っぱられない数と覚える数は固定と同じで、選び直したときに追従する。回数で飽和は 3 回選べば覚える数が増えるが、何度も選び直した語の加点が上限まで育ち、最悪の数が下がる。
- 文脈があるときの加点を 0.75 にした。文脈のある組で、ほかの文脈で選び直しうる語との点差が最も小さいのは 0.95 (「自然」のあとの科学と化学) で、加点 1 からこれが崩れる。llama.cpp の版で点数が 0.1〜1 nat 動くので、0.95 の直下ではなく 0.75 にした。
- 左文脈が空のときの加点を 3.0 にした。左文脈が空なら zenz に手がかりが無く、測った組で B が文脈の無い場面は無いので、引っぱられる数は変わらない。3.0 (尤度比で約 20 倍) より上げても覚える数は 1 件 (行頭の「かんじ」の漢字、点差 3.05) しか増えず、zenz が強く推す候補 (「いがい」の以外と遺骸は点差 6.4) まで入れ替える。
- 「最悪」の 2 組は、どの加点でも 0.5 以上なら崩れる。帰や進を、zenz がほかの語を 1 位に置く文脈で選び直したあとに、「卵が」や「入会を」で起きる。点差が 0.3 しか無い組で、学習なしでも zenz の確信は弱い。

コーパスの 2 周目は学習なしと同じ 198/206 で、headless の Neovim で打った結果 (`LEARNING=on PASSES=2 tests/nvim/corpus.sh`) も区間ごとに学習なしと一致した。
外れる 8 区間のうち 5 区間は文脈があって点差が 0.95 以上 (「機会」1.82、「機械」6.15、「早い」2.47、「意思」1.91、「降り」0.95)、1 区間は行頭で点差が 3.05 (「漢字」)、1 区間は生成した表記 (「コーヒー」) で、加点の届く範囲の外にある。
残る行頭の「速い」(点差 2.44) は 1 回選べば覚える大きさだが、同じ文のあとで同じ見出しの「早い」を選び直すので、2 周目には最後に選び直した語が「早い」になっている。

数字は、zenz のモデルと llama.cpp の版、SKK 辞書、場面の選び方で決まる。人名と左文脈の無い語の答え、対になる文脈の場面は手で選んだもので、加点の上限を決めた組 (「自然」のあとの科学) も 1 件である。

## 開発環境

NixOS / nix で `nix develop` に入ると、cargo、llama.cpp のビルドに要る cmake と libclang、Neovim、[検査](#検査)の道具が揃い、blink.cmp のパスが `RINZE_BLINK` に入る。

```sh
nix develop
cargo test --workspace           # モデルの要らないテスト
tests/lint.sh                    # フォーマット、リンタ、不要なコード、複雑性の検査 (lua か rust を渡すと片方だけ)
nix build                        # result/bin/rinzed (モデルと辞書の既定値を持つラッパー)
nix flake check                  # rinzed とプラグインのビルド、tests/lint.sh、既定のソケットのパスの一致 (Lua 側)、cmd を省いた起動 (tests/nvim/default_cmd.lua)、Linux では fcitx5 のアドオンのテスト
```

rinzed と Neovim プラグインは既定のソケットのパスを別々に組み立てる。
両者が同じパスを返すことは `crates/rinze-socket/tests/fixtures/default_socket.json` の表で確かめる。Rust 側の規則は `rinze-socket` の 1 か所にあり、rinzed と rinze-client が使う。
Rust 側は `cargo test --workspace` (と `nix build`) に含まれ、Lua 側は次で走らせる。

```sh
nvim --headless --clean -l tests/nvim/default_socket.lua
```

x86_64 では flake が `RUSTFLAGS` で AVX2 などを明示する。指定しないと ggml の SIMD が無効になり、変換が約 5 倍遅くなる。

### 検査

`tests/lint.sh` は次の道具を走らせ、`nix flake check` の `lint-lua` と `lint-rust` も同じものを走らせる。

| 対象 | フォーマッタ | リンタと不要なコード | 複雑性 |
| --- | --- | --- | --- |
| Lua (`nvim`、`tests`、`nix/demo.lua`) | stylua (`.stylua.toml`) | luacheck (`.luacheckrc`)。未使用の変数、引数、値 | luacheck の循環的複雑度 (10 まで) |
| Rust | rustfmt | clippy (`-D warnings`、lint の設定は `Cargo.toml` の `[workspace.lints]`)。`unreachable_pub` で外から見えない `pub` を `pub(crate)` にさせ、使われていなければ rustc の `dead_code` が見つける。使われていない依存クレートは cargo-shear | clippy の `cognitive_complexity` (15 まで)、`too_many_lines` (100 行まで)、`too_many_arguments` (7 個まで)。しきい値は `clippy.toml` |

フォーマットを直すには `stylua nvim tests nix` と `cargo fmt` を走らせる。
しきい値を超える既存の関数は、その関数に印を付けて許している。Lua は `-- luacheck: ignore 561`、Rust は `#[expect(clippy::…)]` で、`git grep -e 'luacheck: ignore' -e 'expect(clippy::'` で一覧できる。`#[expect]` は lint が出なくなると警告になるので、関数を分けたら印も外す。

### モデルと辞書

どちらもリポジトリには入れず、flake が取得する。

### 複数の辞書

rinzed は `--dict` を繰り返して複数のシステム辞書を受け取る。読み込むときに 1 つの辞書に合わせ、同じ見出しの候補は渡した順に、先の辞書にある語を除いて後ろに続ける。注釈は先の辞書のものを残す。
並べ替えは合わせた候補全体に zenz でかけるので、辞書の順が効くのは abbrev (辞書の順のまま出す) と、点数づけに失敗したときだけである。
ユーザー辞書の `skk-ignore-dic-word` は合わせた候補から除き、`X` でシステム辞書の語を消すときに書く注釈は、その語を持つ最初の辞書の書き方にする。

既定の辞書は、辞書を足したときの影響を次のように測って決めた。起動時間と常駐メモリは `SKK-JISYO.L` に辞書を足した組ごとに 5 回起動し、待ち受けを始めるまでの時間の中央値と、そのときの RSS を取った。
コーパスは学習ありで 1 周打ち、rinzed が出す点数づけ 1 回ごとの所要時間の中央値、点数をつけた候補の延べ数、打ち終えたときの RSS を取った (各 1 回、16 コアの x86_64 で rinzed は 8 スレッド、`cargo build --release`)。
数字は[常駐メモリ](#常駐メモリ)の削減のあとに測り直したもので、RSS のうち約 72 MB はモデルのファイルの写し。

| 辞書 | 起動 (ms) | RSS 起動時 (MB) | RSS コーパス後 (MB) | 点数づけの回数 / 候補の延べ数 | 点数づけの中央値 (ms) | 1 位正解率 |
| --- | --- | --- | --- | --- | --- | --- |
| L | 75 | 114 | 124 | 157 / 1548 | 29.5 | 198/206 |
| L + jinmei | 67 | 115 | 125 | 159 / 1600 | 30.1 | 198/206 |
| L + geo | 83 | 120 | 130 | 160 / 1575 | 29.9 | 198/206 |
| L + station | 68 | 115 | 125 | 157 / 1548 | 30.0 | 198/206 |
| L + propernoun | 64 | 114 | 125 | 157 / 1549 | 30.2 | 198/206 |
| L + fullname | 72 | 116 | 126 | 157 / 1548 | 30.5 | 198/206 |
| **L + jinmei + geo + station + propernoun** | **102** | **123** | **133** | **160 / 1624** | **30.5** | **198/206** |
| 上 + fullname | 106 | 125 | 135 | 160 / 1624 | 31.0 | 198/206 |

- どの組でも、コーパスの全 206 区間で Space の回数と最初の候補が L だけのときと同じだった。足した辞書の候補 (人名、地名) は zenz が下に置く。
- 起動時間と常駐メモリはほぼ geo (11 万見出し) の分で、起動に約 10 ms、RSS に約 6 MB を足す (辞書を文字列ごとに確保していたときは約 110 ms と約 44 MB だった)。起動は rinzed が常駐するあいだ 1 回なので、地名を引ける利点を取った。
- 点数づけの所要時間は候補の数とともに増える。jinmei は一般の読みに名前を足す (`かんじ` は 12 件から 23 件になり、最初の点数づけが 17〜20 ms から 23〜26 ms になった。`timing` の example で 5 回ずつ)。候補の最も多い読み (`こう` 239 件、`しょう` 174 件) はほぼ L の候補なので、最悪の場合は変わらない。
- fullname (有名人の姓名、2006 年まで) は費用はほぼ無いが、日常の入力で引く見出しが少ないので既定から外した。`override` で足せる。
- skk-dev/dict の辞書には外来語のカタカナ表記がほとんど無い。「マヨネーズ」(`まよねーず`) はどの辞書にも無く、`こーひー` は L の「珈琲」だけなので、「コーヒー」は辞書を足しても zenz の生成した表記のまま出る。生成した表記は[学習](#学習)の対象でないので、選び直しても覚えない (コーパスで学習の履歴に書いた 7 件は L だけのときと同じだった)。

測り直すには、`tests/nvim/corpus.sh` と example (`timing` など) の `RINZE_DICT` に辞書を `:` 区切りで渡す。`timing` は同じ問いの 2 回目から rinzed の覚えた点数を返すので、並べ替えの所要時間は最大値 (1 回目) を見る。

### モデルが要るテスト

```sh
# 並べ替えが試作 (rust-spike) と同じ順になることを 40 件で確かめる。学習なしで並べる。点数が llama.cpp の最適化に依るので release で走らせる
cargo test --release -p rinzed

# headless の Neovim で rinzed を自動起動させ、実際の打鍵でバッファとコマンドラインに入力した結果を確かめる。
# 一時ディレクトリのソケット、ユーザー辞書、学習の履歴を使い、利用者のファイルには触れない。RINZED で rinzed を差し替えられる
cargo build --release -p rinzed
tests/nvim/run.sh
RINZED=result/bin/rinzed tests/nvim/run.sh

# blink.cmp との連携を、default preset と enter preset (上書きあり、なし) で確かめる。
# コマンドラインで rinze がかなのモードの間は blink.cmp のコマンドラインのメニューが出ず、ASCII モードの間は出ることも確かめる。RINZE_BLINK も要る
tests/nvim/blink.sh
```

`RINZE_MODEL` と `RINZE_DICT` (blink.sh では `RINZE_BLINK` も) が無ければ、モデルが要るテストは何もせずに通る。

### 日常の文章での 1 位正解率

`crates/rinze-engine/tests/fixtures/corpus.tsv` に、日常の文章を SKK の打鍵で書いたコーパスがある。1 行が 1 文で、期待する文と打鍵列をタブで区切り、打鍵列の `{表記}` はその直前までの打鍵で変換が始まり、表記が出るまで候補を送ることを表す。

```sh
cargo build --release -p rinzed
tests/nvim/corpus.sh             # RINZED で rinzed を、CORPUS でコーパスを差し替えられる。RINZE_DICT は : 区切りで複数の辞書を渡せる
PASSES=2 tests/nvim/corpus.sh    # 1 周目で学習した状態で 2 周目を打つ。LEARNING=off で学習を止める
```

headless の Neovim で実際の rinzed に打鍵を送り、変換する区間ごとに、期待する表記がその場か一覧に出るまで Space を送る。区間ごとに `文の番号 期待する表記 Space の回数 最初の候補` を出し、最後に次を出す。期待する文と違うバッファになった文があれば 1 で終了する。

- 1 位正解率: 最初の候補が期待する表記だった区間の割合。
- Space の回数の分布: 期待する表記が出るまでに送った Space の回数ごとの区間の数。4 回目から一覧で、一覧に出た回数で数える。
- 届かなかった区間: 生成した表記まで送り切っても期待する表記が出ず、辞書登録に入った区間。

数字は SKK 辞書、ユーザー辞書と学習の履歴 (どちらも空の一時ファイルから始める)、zenz のモデルと llama.cpp の版、左文脈 (Neovim の行のカーソルより前) で決まる。同じ版で走らせれば同じ数字になる。
周ごとに区間の結果と集計を出し、2 周目以降はそれまでの周で選び直した候補を覚えた状態で打つ。
状態機械だけで確かめられること (打鍵列が期待する文になること、変換の始まる位置) は、変換が常に期待する表記を返すものとして `cargo test -p rinze-engine` が同じコーパスで確かめる。
llama.cpp の版が変わると点数が 0.1〜1 nat 動くので、`llama-cpp-2` は `=` で版を固定している。

## Neovim

`nvim/` を runtimepath に加え (Nix では `rinze-nvim`、[入れ方](#入れ方))、`setup` を呼ぶ。ソケットに接続できなかったときは `cmd` で rinzed を起動する。
`cmd` の既定は `{ 'rinzed' }` で、flake の `rinzed` が PATH にあればモデルと辞書の既定値で起動する。flake の外で入れた rinzed では、モデルと辞書を引数で渡す。

```lua
require('rinze').setup({
  -- flake の rinzed が PATH にあれば cmd は要らない
  cmd = { 'rinzed', '--model', '/path/to/ggml-model-Q5_K_M.gguf', '--dict', '/path/to/SKK-JISYO.L', '--dict', '/path/to/SKK-JISYO.jinmei' },
})
-- C-j は rinze の中で SKK の C-j (確定、ひらがなに戻る) に使うので、オンオフには別のキーを割り当てる
vim.keymap.set('i', '<C-l>', function() require('rinze').toggle() end)
vim.o.statusline = "%f %{v:lua.require'rinze'.status()}"
```

`:RinzeEnable` `:RinzeDisable` `:RinzeToggle` でも切り替えられる。有効な間は挿入モードの印字可能文字と Space、Enter、BackSpace、`C-g`、`C-j`、`C-q`、Esc を rinze が受け取る。

- 割り当ては挿入モードの間だけ、そのバッファにバッファローカルの `<nowait>` で置き、挿入モードを抜けるか別のバッファへ移ると外して、置く前の割り当てを戻す。global な割り当て (mini.pairs など) は書き換えない。
- ほかのプラグインのバッファローカルの割り当て (nvim-ts-autotag の `>` など) より rinze が優先する。同じキーで始まる長い割り当て (llama.vim の挿入モードの `<Leader>llf` など) があっても、続きのキーを `timeoutlen` だけ待たない。
- ASCII モードの間は `C-j` 以外の割り当てを外すので、打鍵は rinze を経由せず、rinze が無効なときと同じに Neovim とほかのプラグインが処理する。
- rinze が処理しなかったキー (見出しの無いときの Enter、BackSpace、Space と、Esc) は、rinze が無いときに働く割り当て (mini.pairs の `<CR>` と `<BS>`、picker の `<CR>` と `<Esc>` など) に渡す。割り当てが無ければ Neovim がそのまま処理する。

有効にした直後はひらがなモードで始まる。挿入モードを抜けると入力途中のものを確定するが、モードはそのまま残り、次に挿入モードに入ったときも同じモードで続く。
`C-o` で一時的にノーマルモードに入ったとき (`C-o:` でコマンドラインに入ったときを含む) は確定せず、挿入モードに戻ると見出しの入力を続けられる。戻ったときにカーソルが動いていれば、元の位置に確定する。

確定した文字列は打鍵として Neovim に入力するので、`.` で繰り返せ、`u` は 1 回の挿入をまとめて戻す。
未確定文字列があるときにカーソルを動かすか、挿入モードのまま別のウィンドウへ移ると、未確定文字列を表示どおりに元の位置へ確定する。

`C-q` は端末のフロー制御 (XON) と同じコードだが、Neovim は端末を raw モードにしてフロー制御を切るので、Neovim の動いている間は rinze に届く (tmux の中で確かめた)。届かない場合は、端末エミュレータが `C-q` を自分で使っていないかを確かめる。

`require('rinze').status()` はステータスラインに出す文字列を返し、無効な間は空文字列を返す。表示は `setup` の `mode_labels` で変えられ、既定は次のとおり。`require('rinze').mode()` はモードの名前 (`hiragana` など、通信の `mode` と同じ) を返し、無効な間は nil を返す。

| モード | 既定の表示 |
| --- | --- |
| `hiragana` | `かな` |
| `katakana` | `カナ` |
| `halfwidth-katakana` | `ｶﾅ` |
| `ascii` | `aA` |
| `fullwidth-latin` | `全英` |
ソケットは既定で Linux では `$XDG_RUNTIME_DIR/rinze.sock` (無ければ `/tmp/rinze-$USER.sock`)、macOS では `~/Library/Caches/rinze/rinze.sock` で、`setup` の `socket` で変えられる。
macOS で `$TMPDIR` を使わないのは、nix develop などで値が変わり、同じ利用者のプロセスどうしで一致しないことがあるため。
Unix ドメインソケットのパスには上限 (Linux で 107 バイト、macOS で 103 バイト) があり、超えると rinzed はモデルを読む前に原因を書いて終了し、プラグインはそれをエラーとして表示する。

Neovim を同時にいくつ開いても rinzed は 1 つだけ動く。rinzed はソケットごとのロックファイル (`rinze.sock.lock`) を生きている間ずっとロックし、ロックを取れなかったものは何もせずに 0 で終了する。プラグインは起動したものが 0 で終了した場合も、先に動いている rinzed が待ち受けを始めるまで待つ。
ロックは rinzed が落ちれば外れるので、ロックを取れた rinzed は残っているソケットを前の rinzed の残骸として消してから bind する。

### コマンドライン

`/` `?` の検索と `:` のコマンドラインでも打てる。コマンドラインは開くたびに無効から始まり、`enable` を呼んだときだけ、そのコマンドラインを抜けるまで有効になる。
`enable` `disable` `toggle` は呼んだときのモードを見て、コマンドラインモードならコマンドラインの rinze を、それ以外なら挿入モードの rinze を切り替えるので、同じ関数をコマンドラインモードの割り当てから呼ぶ。

```lua
vim.keymap.set('c', '<C-j>', function() require('rinze').enable() end)
```

- 挿入モードとは別の接続で、別の入力状態を持つ。コマンドラインは常にひらがなで始まり、挿入モードの有効かどうか、入力モード、見出しは、コマンドラインでの操作の前後で変わらない。
- 打ち方は挿入モードと同じ。Enter は見出しの入力中と変換中は確定だけを行い、未確定のものが無ければコマンドの実行や検索の確定になる。`C-g` は未確定のものがあれば取り消し、無ければ Neovim の `c_CTRL-G` (検索中の次の一致へ移る) になる。
- Esc と `C-c` は割り当てず、Neovim がそのままコマンドラインを抜ける。コマンドラインを抜けると入力途中のものを確定せずに捨て、接続を閉じる。履歴にもバッファにも未確定文字列は残らない。
- `l` で ASCII モードに入ると、挿入モードと同じく `C-j` 以外を rinze が受け取らない。かな系のモードの `/` は abbrev の開始なので、`:s/漢字/文字/` の区切りの `/` は `l` で ASCII モードにしてから打つか、`C-v /` で打つ。
- 割り当ては、有効にしたコマンドラインの間だけカレントバッファにバッファローカルの `<nowait>` で置き、抜けると置く前の割り当てを戻す。rinze が処理しなかったキーは、挿入モードと同じく元の割り当てに渡す。
- 未確定文字列があるときにコマンドラインのカーソルを動かす (`<Left>`、履歴の呼び出しなど) と、挿入モードと同じく元の位置に確定する。
- 確定、辞書登録、`X` での削除、[学習](#学習)は挿入モードと同じに働く。

未確定文字列はコマンドラインの文字列に入れず、カーソルの位置に重ねたフロートで出す。カーソルより後ろの文字列もフロートに続けて描くので、挿入モードの inline の仮想テキストと同じに見える。
コマンドラインに入れる方式では、'incsearch' が `▽` を含む文字列で検索し直して一致が無くなり、画面が検索を始めた位置に戻った。確定すると一致へ移り、次の見出しを打ち始めるとまた戻る (tmux の中で確かめた)。中断したコマンドラインは `▽` ごと履歴に残る。
フロートで出す方式では、コマンドラインには確定した文字列だけが入るので、'incsearch' と 'inccommand' は確定した文字列で動き、見出しの入力中は画面が動かない。
候補の一覧と辞書登録の入力欄は、コマンドラインのすぐ上にカーソルの桁から出す。'cmdheight' が 0 のときと、コマンドラインをほかの UI (noice.nvim など) で描くときは確かめていない。

左文脈は、コマンドラインのカーソルより前の文字列のうち、最後の ASCII の記号か空白より後ろを渡す (`:%s/明日は雨/あした` なら `あした`)。
コーパスの各文の前に `%s/` などを付けて打つと、付けたまま渡したときの 1 位正解率は 198/206 (`%s/`)、199/206 (`%s/きょうは/`)、198/206 (`%s/明日は雨/`) で、付けないとき (198/206) とほぼ変わらず、区間ごとに 4〜5 件が入れ替わるだけだった。
正解率が変わらないので、コマンドの構文を文章として zenz に渡さず、欄の先頭を行頭と同じに扱う方にした。検索の `/` の直後と `:s/` の直後で、学習の加点 (左文脈が空のときの 3.0) が同じになる。

`preedit()`、`mode()`、`status()` は、コマンドラインで有効な間はコマンドラインの状態を返し、それ以外は挿入モードの状態を返す。

blink.cmp のコマンドラインの補完は、打鍵に反応してカーソルより前のコマンドラインでメニューを出す。見出しの入力中にメニューが出ると候補の一覧と重なるので、rinze はコマンドラインで打鍵を受け取る間 (かなのモードと全角英字モード) だけ blink.cmp の設定の `cmdline.enabled` を false にし、ASCII モードに入るか、rinze を無効にするか、コマンドラインを抜けると元の値に戻す。ASCII モードの間は rinze が無効なときと同じく `:` のコマンドなどの補完が出る。blink.cmp の設定に何も足さなくてよい。
全角英字モードでは未確定文字列は無いが、コマンド名やバッファの英単語の候補は全角の文字に一致しないので、補完を止めたままにする。
blink.cmp の内部の設定 (`require('blink.cmp.config').cmdline`) を書き換えるので、blink.cmp 1.10.2 で確かめ、`tests/nvim/blink.sh` が守る。

### blink.cmp との連携

[blink.cmp](https://github.com/saghen/blink.cmp) を使っているなら、`setup` に `blink = true` を渡すと、見出しの入力中 (▽) にその読みの変換候補を blink.cmp のメニューに出す。blink.cmp が無いか、`blink` を渡さなければ何も変わらない。

```lua
require('rinze').setup({ blink = true })
```

- メニューの並びは Space で変換したときと同じ (zenz の点数と学習の加点) で、`Asita` と打てば `Asita` の Space で送る順に「明日」「朝」「晨」が出る。出すのは送りがなの無い見出しの辞書の候補だけで、送りがなの入力中、abbrev、辞書登録の入力欄では出さない。生成した表記も出さない。
- メニューで受け入れる (`default` preset なら `C-y`) と、その候補で見出しを確定する。Space で送って確定したのと同じに扱い、先頭以外の候補なら[学習](#学習)の履歴に書く。
- `C-n` などで選ぶと、blink.cmp は候補をバッファに仮に入れる (`completion.list.selection.auto_insert`)。その状態で rinze のキーを打つと、SKK で候補の表示中に次の文字を打ったときと同じく、仮に入れた候補を確定してからそのキーを処理する。Enter はその確定だけを行い、改行しない。
- メニューに候補が見えていても、選ぶまで何も確定しない。Space での変換、5 候補目からの一覧、Enter での読みのままの確定はそのまま使える。メニューで並べた読みをそのまま Space で変換すると、並べ替えをやり直さない (`かんじ` の Space の中央値が、メニューを出さないときの 34〜36 ms から 0.12〜0.19 ms になった。`tests/nvim/blink.sh` で 5 回ずつ)。
- 候補はキーを送る接続とは別の接続で `lookup` で問い合わせ、キーの処理は問い合わせを待たない。問い合わせの途中に来た問い合わせは最新の 1 件だけ残す。`tests/nvim/blink.sh` では、Space を除く 1 打鍵の処理の中央値が連携ありで 0.06〜0.10 ms、なしで 0.02 ms (それぞれ 95 打鍵、`cargo build --release` のバイナリで 2 回と `nix build` のバイナリで 1 回) で、`Nihongonyuuryoku` を一気に打ち終えてから最後の読みのメニューが出るまでは 20〜22 ms だった。
- ソースは `rinze` という名前で rinze が blink.cmp に足すので、blink.cmp の設定の `sources` に書かなくてよい。メニューにはこのソースだけを出し、ほかのソース (buffer、LSP など) の候補は混ぜない。確定した文字列は打鍵としてバッファに入るので、そのあとは普段どおりほかのソースの補完が働く。

`default` preset のキーは rinze のキーと重ならない。`enter` preset では、メニューの表示中の Enter が先頭の候補の受け入れになり、SKK の「▽ で Enter は読みのまま確定」と意味が変わる。読みのまま確定したい場合は、見出しの入力中だけ Enter を rinze に渡すよう上書きする。

```lua
require('blink.cmp').setup({
  keymap = {
    preset = 'enter',
    ['<CR>'] = {
      function(cmp)
        if require('rinze').preedit() == '' then
          return cmp.accept()
        end
      end,
      'fallback',
    },
  },
})
```

ほかに rinze が受け取るキー (印字可能文字、Space、BackSpace、`C-g`、`C-j`、`C-q`、Esc) を blink.cmp の `keymap` に割り当てる場合も、同じく見出しの入力中は `fallback` に回す。rinze のキーの割り当ては `<Cmd>` を右辺にしているので、blink.cmp の `fallback` から呼ばれても、続けて打ったキーと順序が入れ替わらない。

blink.cmp が割り当てたキーは、ほかのバッファローカルの割り当てと違って rinze が奪わず、blink.cmp が先に受け取る。blink.cmp の `fallback` は挿入モードに入ったときに無かったバッファローカルの割り当ての代わりに global な割り当てを探すので、rinze はそのキーだけ挿入モードの間 global に置き、抜けるときに置く前の割り当てを戻す。

blink.cmp は受け入れ (`C-y`) と選択 (`C-n`) を `vim.schedule` で後回しにするので、rinze はキーを処理する前に `vim.wait(0)` で後回しの処理を先に済ませ、受け入れの直後に間を空けずに打ったキーを受け入れのあとに処理する。仮に入れた候補を確かめて取り消すのに blink.cmp の内部の `blink.cmp.completion.list` (`preview_undo`、`get_selected_item`、`undo_preview`) を使っている。blink.cmp 1.10.2 で確かめ、`tests/nvim/blink.sh` が守る。

## fcitx5

Linux では fcitx5 の入力メソッドとして rinze を使える。アプリの入力欄で打つと、Neovim と同じ rinzed が変換し、左文脈も入力欄から取る。

アドオン (`fcitx5/`) は C++ で書き、表示と fcitx5 とのやりとりだけを受け持つ。rinzed との通信、応答の解釈、rinzed の起動、先読み、左文脈から未確定文字列を除く処理は Rust の `rinze-client` にあり、アドオンはそれを静的にリンクして C ABI で呼ぶ。
ヘッダ `crates/rinze-client/include/rinze_client.h` は cbindgen で `src/ffi.rs` から作り、`cargo test -p rinze-client` がずれを見つける。作り直すには `RINZE_WRITE_HEADER=1 cargo test -p rinze-client header` を走らせる。
アドオンの共有ライブラリは、`rinze_` で始まる関数と fcitx5 のアドオンの入口だけを外に出す。Rust の std のシンボルは出さない。

### NixOS で入れる

flake の `fcitx5-rinze` を fcitx5 のアドオンに足す。アドオンは動かす fcitx5 と同じ版に対してビルドする必要があるので、`inputs.rinze.inputs.nixpkgs.follows` でシステムの nixpkgs に揃える。

```nix
# flake.nix の inputs
rinze = {
  url = "git+file:///path/to/rinze";
  inputs.nixpkgs.follows = "nixpkgs";
};
```

```nix
# NixOS のモジュール
{ inputs, pkgs, ... }:
{
  i18n.inputMethod = {
    enable = true;
    type = "fcitx5";
    fcitx5.addons = [ inputs.rinze.packages.${pkgs.stdenv.hostPlatform.system}.fcitx5-rinze ];
  };
}
```

アドオンは PATH の `rinzed` を起動するので、flake の `rinzed` を home-manager の `home.packages` などで入れる。fcitx5 を systemd の user unit で動かしていて、unit の PATH に `/etc/profiles/per-user/$USER/bin` が入っていれば、home-manager で入れた rinzed が見つかる。

反映して fcitx5 を起動し直したら、fcitx5-configtool の入力メソッドの一覧 (または `~/.config/fcitx5/profile`) に rinze を足す。

### fcitx5-skk と並べて使う

fcitx5-skk と rinze は、同じグループにも別のグループにも置ける。

- 同じグループに `keyboard-us`、`skk`、`rinze` を並べた場合、`TriggerKeys` (既定は `Control+space`) は直接入力と、最後に使った入力メソッドを切り替える。skk と rinze の切り替えには `EnumerateForwardKeys` を割り当てるか、トレイのメニューを使う。
- グループを分けた場合 (`keyboard-us` と `skk` のグループ、`keyboard-us` と `rinze` のグループ)、`EnumerateGroupForwardKeys` (既定は `Super+space`) でグループを切り替える。

### fcitx5 での打ち方

[打ち方](#打ち方)は Neovim と同じで、fcitx5 では次のように振る舞う。

- 打鍵ごとに rinzed の応答を待ってから処理する。rinzed が処理しなかったキー (未確定のものが無いときの Enter、BackSpace、Space など) は、確定した文字列を入れたあとでアプリに渡す。
- ASCII モードの間は、`C-j` 以外のキーを rinzed に送らずにアプリに渡す。
- Escape は、入力途中のものがあれば `C-g` と同じく 1 段戻し、無ければアプリに渡す。
- rinzed が扱わないキー (矢印、Tab、Ctrl の付いたほかのキーなど) は、入力途中のものがあれば表示どおりに確定してからアプリに渡す。
- 候補一覧の表示中は、`x` と Space に加えて、fcitx5 の全体の設定のページ送りのキー (`PrevPage` と `NextPage`。既定は Up と Down) でもページを送る。パネルの矢印と候補のクリックも使える。
- 入力欄からフォーカスが外れたときと、アプリが入力欄をリセットしたときは、入力途中のものを確定せずに捨て、学習の履歴にも書かない。入力モードは残る。入力メソッドを切り替えたときは、表示どおりに確定する。
- 未確定文字列はすべて fcitx5 の `DontCommit` にしてあるので、フォーカスが外れても fcitx5 は確定しない。Wayland の text-input-v3 ではアプリが残すかを決め、入れ子の sway では GTK4 と Firefox は捨て、Chrome は未確定文字列を `▼機会` のように印ごと本文に残した。

### fcitx5 での表示

- 未確定文字列は、アプリが対応していればアプリの中に、そうでなければパネルに出す。
- 候補一覧、辞書登録の入力欄、辞書から消すかの問いはパネルに出す。候補一覧の上にページ (`[2/34]`) を出す。
- 入力モードは入力メソッドのサブモードのラベル (`かな` `カナ` `ｶﾅ` `全英` `aA`) とステータスエリアの項目に出し、切り替えたときは fcitx5 の入力メソッドの情報として短く出す。
- トレイのメニューからモードを選ぶと、入力途中のものを確定してから、切り替えのキー (`q` `C-q` `l` `L` `C-j`) を送ってそのモードにする。

### rinzed の起動と応答の待ち

アドオンは、入力欄で rinze が有効になったときと打鍵のときに rinzed に接続し、接続できなければ rinzed を `--socket` 付きで起動する。起動は待たない。
rinzed がモデルを読み終えて待ち受けを始めるまでの打鍵はアプリにそのまま渡し、パネルに `rinze: rinzed を起動しています` を出す。待ち受けを始めると、打鍵が無くても表示を消す。
起動に失敗したとき (PATH に rinzed が無い、モデルが無いなど) は、理由 (`rinzed が PATH に無い`、rinzed が標準エラー出力に書いた最後の数行) をパネルに出し、打鍵はアプリに渡す。5 秒たつと、次の打鍵で起動し直す。
打鍵ごとに rinzed の応答を待つ間、fcitx5 は次の打鍵を溜めておき、応答のあとで順に渡す。CPU が詰まっていて点数づけが遅いときも、10 秒までは待って変換する。
10 秒待っても応答が無ければ、未確定文字列をそのまま残し、パネルに `rinze: rinzed が 10 秒以内に応答しなかった。入力途中のものは残してあり、次の打鍵で応答を待ち直す` を出す。要求は rinzed に届いていて入力途中のものも rinzed に残っているので、その打鍵はアプリに渡さない。
次の打鍵では、遅れた応答を 1 秒まで待って読み、その応答で確定したものも入れてから、その打鍵を送る。遅れた応答のあとに次の打鍵を処理するので、遅れた Space のあとでもう一度 Space を打つと次の候補に進む。
次の打鍵でも応答が無ければ、rinzed が止まっているものとして接続を捨て、`rinzed が応答しないので、入力途中のものを捨てた` を出して打鍵をアプリに渡す。rinzed 側の入力途中のものはそのとき失われる。
一度 10 秒待ち切れなかったあとは、rinzed からどれかの応答が届くまで、どの入力欄でも 1 秒で諦めて打鍵をアプリに渡す。止まった rinzed に、打鍵のたびに 10 秒固まることはない。
Neovim と同じ既定のソケットを使うので、どちらが起動しても rinzed は 1 つで、ユーザー辞書と学習の履歴を共有する。

接続は入力欄 (fcitx5 の入力コンテキスト) ごとに 1 つで、入力欄が無くなると閉じる。fcitx5 の「入力状態を共有」(`ShareInputState`) の設定によらず、入力モードは入力欄ごとに持つ。

### 先読み

見出しの読みが変わって 200 ms そのままなら、キーを送る接続とは別の接続で `lookup` を投げる ([blink.cmp との連携](#blinkcmp-との連携)と同じ仕組み)。応答は使わない。
rinzed は最後につけた点数を覚えているので、読みを打ってから点数づけが終わるのを待って Space を打つと、並べ替えを待たない。`こう` (候補 241 件) を打って 500 ms 後の Space は、先読みありで中央値 0.88〜0.93 ms、なしで 72〜79 ms だった。打った直後の Space は先読みを投げる前なので先読みが効かず、先読みありで 78〜83 ms、なしで 72〜73 ms だった。読みが変わる打鍵の中央値は 0.04〜0.06 ms で、先読みを待たない (testfrontend でそれぞれ 5 回と 30 回を 3 度、16 コアの x86_64)。
200 ms 待つのは、打っている途中の読みに点数をつけないため。点数づけは一度に 1 つずつ走るので、途中の読み (`き` なら候補 139 件) に点数をつけている間は、Space での変換が待たされる。
`stress-ng --cpu 32` で 16 コアを埋めた間に `きかい` などを 80 ms おきに打ってすぐ Space を打つと、読みが変わるたびに先読みしたときは Space が中央値 1.6 秒、最大 2.8 秒、200 ms 待ってから先読みすると中央値 1.0 秒、最大 2.4 秒だった (16 回ずつ)。

### 左文脈

アドオンは入力欄の surrounding text のカーソルより前を左文脈として送る。取れない入力欄では空の左文脈を送るので、候補は文脈の無い順に並ぶ。
Firefox は未確定文字列を本文に入れた surrounding text を送り、本文が変わるまで同じものを送り続ける。アドオンは、前に surrounding text が変わってから表示した未確定文字列と突き合わせて、それを除く。未確定文字列の全体がカーソルをまたぐ位置にそのまま入っているときだけ除くので、本文に書いた ▽ や ▼ は除かない。

| アプリ | 左文脈 | 確かめ方 |
| --- | --- | --- |
| GTK4 (zenity 4.2.2) | 取れる | 入れ子の sway で打った |
| GTK3 (yad 15.0) | 取れる | 入れ子の sway で打った |
| Google Chrome 157 | 取れる | 入れ子の sway で打った |
| Firefox 159 | 取れる。未確定文字列を除いて使う | 入れ子の sway で打った |
| Electron 45 | 既定のフラグでは取れない (`invalid`)。`--wayland-text-input-version=3` を付けると取れる | 入れ子の sway で打った |
| Qt6 (kdialog) | 取れない | 入れ子の sway で打った |
| Ghostty | 取れない | 確かめていない (ソースを読んだだけ) |
| XIM のアプリ | 取れない | 確かめていない (ソースを読んだだけ) |

### 診断

環境変数 `RINZE_FCITX_DEBUG` を立てて fcitx5 を動かすと、打鍵ごとに、左文脈の取り方 (`surrounding`、`未確定文字列を除いた`、`invalid`、`capability なし`) と送った左文脈をパネルの下段とログに出す。ログには surrounding text とカーソルの位置もそのまま出す。アプリごとに左文脈が取れるかを確かめるのに使う。
立てていない間は、打鍵の内容をログに出さない。

```sh
RINZE_FCITX_DEBUG=1 fcitx5 -r --verbose=rinze=5
```

| 環境変数 | 意味 |
| --- | --- |
| `RINZE_SOCKET` | 接続するソケット。無ければ既定のソケット |
| `RINZE_RINZED` | 接続できなかったときに起動する rinzed。無ければ PATH の `rinzed` |
| `RINZE_FCITX_DEBUG` | 上の診断を出す |
| `RINZE_FCITX_NO_PREFETCH` | 先読みをやめる。先読みの効果を測るのに使う |

### fcitx5 のテスト

```sh
nix build .#checks.x86_64-linux.fcitx5-rinze -L
```

fcitx5 の testfrontend でアドオンを画面なしで読み込み、打鍵を送って、確定した文字列、未確定文字列、パネル、入力モードの表示を確かめる (`fcitx5/test/testrinze.cpp`)。
`fcitx5/test/run.sh` が場面ごとに一時ディレクトリのソケット、ユーザー辞書、学習の履歴で rinzed を用意し、利用者のファイルと既定のソケットには触れない。場面は次のとおりで、所要時間もログに出す。

- 打鍵: 変換と確定、送りあり、左文脈による順位、未確定文字列の混ざった surrounding text、候補一覧の選択とページ送り、辞書登録の入力欄、辞書から消すかの問い、5 つの入力モードとトレイのメニュー、ASCII モードで rinzed に送らないこと、Ctrl のキー、Escape、矢印、BackSpace、フォーカスが外れたときに捨てて学習に書かないこと、入力欄を閉じると接続を閉じること
- 自動起動: rinzed が動いていない状態で有効にしたとき、打鍵を待たせずにアプリへ渡し、待ち受けを始めると表示が戻ること
- 遅い rinzed (止めて 1.5 秒後に再開する): 1 秒を超えても待って変換すること。止めたままの rinzed: 10 秒で未確定文字列を残して諦め、ほかの入力欄はそのあと 1 秒で諦め、再開したあとの打鍵で遅れた応答の確定を失わないこと
- PATH に rinzed が無い場合、rinzed がモデルを読めずに終了する場合 (打鍵が無くても理由をパネルに出すこと)、応答しない rinzed (受け付けるだけのソケット) の場合 (最初の 10 秒のあとは打鍵ごとに 1 秒で諦めること)
- 先読みのあり、なしでの Space の所要時間

あわせて、共有ライブラリが外に出すシンボルを確かめる (`fcitx5/test/exports.cmake`)。
手元で cmake でビルドする場合は、`cargo build --release -p rinze-client` のあとで `nix develop .#fcitx5-rinze` に入り、`-DRINZE_CLIENT_LIB=target/release/librinze_client.a -DRINZE_CLIENT_INCLUDE=crates/rinze-client/include` を渡して `fcitx5/` をビルドし、ビルドディレクトリで `RINZED=<rinzed のパス> ctest --output-on-failure` を走らせる。
