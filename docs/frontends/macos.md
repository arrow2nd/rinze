# macOS

macOS では入力メソッド (`rinze.app`) として rinze を使える。アプリの入力欄で打つと、Neovim と同じ rinzed が変換し、左文脈も入力欄から取る。

アプリ (`macos/`) は Swift で書き、InputMethodKit とのやりとりと表示だけを受け持つ。rinzed との通信、応答の解釈、rinzed の起動、左文脈から未確定文字列を除く処理は [fcitx5 のアドオン](fcitx5.md)と同じ Rust の `rinze-client` にあり、静的にリンクして C ABI で呼ぶ。
Xcode のプロジェクトは持たず、`swiftc` で直接組む。

導入手順は [macOS で入れる](../install/macos.md)、テストは [macOS のテスト](../development/testing.md#macos-のテスト) を参照。

## macOS での打ち方

[打ち方](../usage/typing.md)は Neovim と同じで、macOS では次のように振る舞う。

- 打鍵ごとに rinzed の応答を待ってから処理する。rinzed が処理しなかったキー (未確定のものが無いときの Enter、BackSpace、Space など) は、確定した文字列を入れたあとでアプリに渡す。
- ASCII モードの間は、`C-j` 以外のキーを rinzed に送らずにアプリに渡す。
- Escape は、入力途中のものがあれば `C-g` と同じく 1 段戻し、無ければアプリに渡す。
- rinzed が扱わないキー (矢印、Tab、Cmd や Option の付いたキー、`C-g` `C-j` `C-q` 以外の Ctrl の付いたキーなど) は、入力途中のものがあれば表示どおりに確定してからアプリに渡す。
- 候補一覧の表示中は、`x` と Space に加えて Up と Down でもページを送る。
- 入力欄からフォーカスが外れたときは、入力途中のものを確定せずに捨て、学習の履歴にも書かない。入力モードは残る。入力ソースを切り替えたときと、アプリが確定を求めたときは、表示どおりに確定する。

## macOS での表示

- 未確定文字列は下線を付けてアプリの中に出す。
- 候補一覧、辞書登録の入力欄、辞書から消すかの問い、rinzed の起動や失敗の知らせは、カーソルの下のパネルに出す。候補一覧の下にページ (`[2/34]`) を出す。
- 候補は選択キーで選ぶ。パネルの候補はクリックできない。
- 入力モードはメニューバーの入力メニューのアイコン (`あ` `ア` `ｱ` `Ａ` `A`) に出し、切り替えたときはカーソルの下に 1 秒だけラベル (`かな` `カナ` `ｶﾅ` `全英` `aA`) を出す。

## 入力モードと入力ソース

5 つの[入力モード](../usage/modes.md)を、それぞれ macOS の入力ソース (`io.github.arrow2nd.inputmethod.rinze.hiragana` など) として `Info.plist` に定義している。

- 切り替えのキー (`q` `C-q` `l` `L` `C-j`) でモードが変わると、メニューバーの入力ソースもそのモードに切り替える。
- メニューバーの入力メニューからモードを選ぶと、入力途中のものを確定してからそのモードにする。JIS キーボードの かな キーはひらがな、英数キーは ASCII を選ぶ。
- 入力モードは入力欄ごとに持つ。フォーカスが移ると、メニューバーの表示をその入力欄のモードに合わせ直す。
- システム設定の入力ソースで外したモードには、メニューバーの表示は切り替わらない。切り替えのキーでそのモードにすることはできる。

アイコンは `macos/Resources/` の TIFF で、`swift macos/icons.swift macos/Resources` で作り直せる。

## rinzed の起動と応答の待ち

起動と応答の待ち方は `rinze-client` が受け持つので、[fcitx5 と同じ](fcitx5.md#rinzed-の起動と応答の待ち)になる。入力欄で rinze が有効になったときと打鍵のときに rinzed に接続し、接続できなければ rinzed を `--socket` 付きで起動して、待ち受けを始めるまでの打鍵はアプリに渡す。

入力メソッドのプロセスの PATH には利用者のシェルの設定が入らないので、起動する rinzed は次の順に決める。

1. `defaults` の `rinzed`
2. `Info.plist` の `RinzedPath`。nix のパッケージは flake の `rinzed` を、`macos/build.sh` は環境変数 `RINZED` を書く
3. PATH の `rinzed`

[rinzed を常駐させて](../install/flake.md#rinzed-を常駐させる)いれば、アプリは繋ぐだけで起動しない。
Neovim と同じ既定のソケットを使うので、どちらが起動しても rinzed は 1 つで、ユーザー辞書と学習の履歴を共有する。接続は入力欄ごとに 1 つ持つ。

## 左文脈

カーソルより前 (未確定文字列があればその前) を UTF-16 で 80 単位まで入力欄から取り、左文脈として送る。`rinze-client` が末尾 40 字に絞る。
アプリが範囲の文字列を返さないときは空の左文脈を送るので、候補は文脈の無い順に並ぶ。アプリごとに取れるかは確かめていない。

パスワード欄では macOS が入力メソッドを外すので、rinze に打鍵は届かない。それ以外に、入力を残さないよう求める入力欄を見分ける処理は入れていない。

## 設定と診断

設定は `defaults` で渡し、アプリを起動し直すと効く (`pkill -x rinze`。次の打鍵で macOS が起動する)。

| キー | 意味 |
| --- | --- |
| `socket` | 接続するソケット。無ければ既定のソケット |
| `rinzed` | 接続できなかったときに起動する rinzed |
| `debug` | 打鍵ごとに、左文脈の取り方 (`surrounding`、`未確定文字列を除いた`、`取れない`) と送った左文脈をパネルに出す |

```sh
defaults write io.github.arrow2nd.inputmethod.rinze debug -bool true
pkill -x rinze
```

rinzed に繋げなかった理由などはパネルに出し、`NSLog` にも書く。

```sh
log stream --predicate 'process == "rinze"'
```
