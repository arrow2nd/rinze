# モデルと辞書

## モデルと既定の辞書

モデルとシステム辞書はリポジトリに含めず、Nix flake が外部から取得して管理する。具体的な取得元やハッシュは `flake.nix` および `nix/` 配下に定義している。

- **モデル**: `zenz-v3.2-small` の量子化モデル（GGUF、CC-BY-SA 4.0）
- **既定の辞書**: `skk-dev/dict` 由来の以下 5 つの辞書（いずれも GPL-2.0-or-later）。文字コードは EUC-JP と UTF-8 の両方に対応している。

| 辞書 | 対象 |
| --- | --- |
| `SKK-JISYO.L` | 基本語彙 |
| `SKK-JISYO.jinmei` | 人名 |
| `SKK-JISYO.geo` | 地名 |
| `SKK-JISYO.station` | 駅名 |
| `SKK-JISYO.propernoun` | 固有名詞（企業・作品など） |

### 既定辞書の選定方針

通常の SKK では辞書を増やすとノイズになる候補が上位に混ざりやすいが、rinze では結合後の全候補を zenz が文脈に応じて並べ替えるため、人名・地名・固有名詞の辞書を加えても日常文の変換精度が落ちにくい。また、`rinzed` は常駐プロセスであり辞書の読み込みは起動時の 1 回で済むうえ、[コンパクトなメモリ表現](../architecture/performance.md#常駐メモリの抑制)を採用しているため、語彙を広くカバーする利点がコストを上回る。

一方で、日常の入力頻度が低い辞書（`fullname` など）は既定から外している。追加の辞書を使いたい場合は flake の [`override`](../install/flake.md#既定値の変更) や `rinzed --dict` で柔軟に組み合わせられる。

## 複数辞書の統合ルール

`rinzed` は `--dict` オプションで複数のシステム辞書を受け取り、起動時に 1 つの辞書へ統合する。

- 同じ見出しに対する候補は渡された順にマージし、重複する語は先の辞書を優先する（注釈も先の辞書のものを残す）。
- 制御文字を含むエントリや、`(` で始まる SKK の Lisp 式候補は安全のため読み込み時に除外する。
- 通常変換では全候補を zenz が並べ替えるため、辞書の指定順が結果に影響するのは abbrev と、[zenz がフォールバックしたとき](typing.md#zenz-が遅れたときや使えないとき)のみである。

## ユーザー辞書

辞書登録した語は、SKK 辞書互換の UTF-8 テキストファイルに保存される（既定は Linux で `$XDG_DATA_HOME/rinze/user.jisyo`、macOS で `~/Library/Application Support/rinze/user.jisyo`、`--user-dict` で変更可能）。

- **単一ライターと原子的な保存**: ユーザー辞書へ書き込むのは `rinzed` のみであり、一時ファイルへの書き込みと同期のあとにリネームして差し替えるため、異常終了時にもファイルが破損しない。
- **システム辞書との対等な扱い**: ユーザー辞書の語はシステム辞書の候補とまとめて zenz でスコアリングし、無条件で先頭に固定しない。文脈に合致する場面で自然に選ばれつつ、別の文脈を邪魔しない設計としている。
- **除外指定の互換性**: `skk-ignore-dic-word` による候補除外は ddskk と互換の書式で読み書きし、システム辞書の候補だけでなく zenz の生成候補にも適用する。
