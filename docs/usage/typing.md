# 打ち方と変換の流れ

rinze の入力操作は SKK（ddskk）に準拠している。SKK の「変換の区切りを自分で指定する」明快さを保ちつつ、候補の順位付けと辞書未登録語の補完を zenz に任せるのが基本的な設計である。

## 基本操作

- **見出し入力と変換**: 大文字で変換の開始（▽）を示し、送り仮名のない語は Space で変換する。送り仮名のある語は、送り仮名の先頭を大文字で打つと変換が始まる（例: `AEmasu` → `あ*え`、`ATte` → `あ*っ`）。
- **候補の選択**: 変換中（▼）に Space で次の候補、`x` で前の候補へ移動する。最初の数候補はその場に表示し、それ以降は候補一覧を表示して選択キー（`asdfjkl`）で選ぶ。SKK 辞書の候補に注釈（`;` 以降、`*` で始まる内部コメントを除く）がある場合は、変換中のカーソル下パネルや候補一覧・補完メニューの右側に表示する。
- **確定と取り消し**: 変換中に次の文字を打つか Enter で確定する。`C-g` で変換や見出し入力を 1 段階取り消す。
- **Enter の挙動**: Enter は常に確定のみを行い、改行しない（ddskk の `skk-egg-like-newline` を有効にした状態と同じ）。
- **`Q` による見出し開始**: `Q` を押すと空の見出し（▽）に入る。見出し入力の途中であれば、それまでの見出しをかなで確定してから新しい見出しに入る。

## 辞書登録と候補削除

- **辞書登録**: 辞書の候補と zenz の生成候補をすべて送り切ると、入れ子対応の辞書登録モードに入る。登録した語は[ユーザー辞書](dictionaries.md#ユーザー辞書)に保存される。
- **候補の削除（`X`）**: 変換中に `X` を押すと、表示中の候補を辞書から除外する確認プロンプトが出る。ユーザー辞書にのみある語はそのまま削除し、システム辞書にある語や zenz の生成候補は `skk-ignore-dic-word` としてユーザー辞書に記録して以後表示しないようにする。削除した候補の[学習](learning.md)履歴もあわせて消去する。
  - なお、一度除外した語を再び辞書登録した場合は `skk-ignore-dic-word` からも取り除くため、再登録後に再び出なくなる不整合が起きない。

## abbrev

かな系のモードで `/` を打つと、英字や記号の見出し入力（abbrev）に入る。Space で SKK 辞書の英字見出しを引いて変換でき、Enter / `C-j` で英字のまま、`C-q` で全角英字にして確定する。

- **zenz で並べ替えない理由**: abbrev は英単語の綴りから日本語表記を引く用途が多いが、英字をそのまま読みとして zenz に渡すと綴りに近いカタカナ語や英字表記ばかりが上位に偏りやすい。そのため abbrev では辞書順（および[学習](learning.md)による先頭昇格）をそのまま使い、表記生成も行わない。

## zenz による表記生成

SKK 辞書に登録されていない語（外来語のカタカナ表記や新語など）を補うため、辞書の候補を送り切ったあと（あるいは辞書に見出しがない場合は最初から）zenz のビーム探索による表記生成を行う。

- **遅延実行**: 表記生成は辞書候補のスコアリングより計算コストが高いため、辞書に見出しがある場合は候補を送り切るまで生成を実行しない。
- **品質フィルタ**: 生成された候補のうち、スコアが極端に低いもの、送り仮名や読みの構造と整合しないもの、ひらがなのままのもの、辞書候補と重複するものは除外する。

## zenz が遅れたときや使えないとき

高負荷で推論が一定時間内に終わらない場合や、モデルを読み込めなかった場合でも、rinze は入力を止めずにフォールバックして変換を続ける。

- 辞書候補は辞書順と[学習](learning.md)履歴のみで並べ替える（最後に選び直した候補が先頭に来る）。
- 表記生成はスキップし、辞書候補を送り切るとそのまま辞書登録に入る。
- 遅延している計算が完了するまでの間、後続の変換も待たせずにフォールバック結果で即座に応答する。
