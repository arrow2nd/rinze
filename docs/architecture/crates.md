# クレート構成と責務分担

rinze は「変換エンジンとデーモン（Rust）」と「表示・入力仲介を担う薄いフロントエンド（Lua / C++ / Swift）」に分離したクライアント・サーバー構成をとる。

## 設計の方針

- **状態とロジックをデーモン側に集約する**: 入力モードや未確定状態、辞書、学習履歴、zenz モデルはすべて常駐デーモン `rinzed` が一元管理する。どのフロントエンドから使っても変換結果や操作感が一致し、ユーザー辞書と学習履歴も自然に共有される。
- **フロントエンドを薄く保つ**: フロントエンドは入力モードや変換状態を自前で解釈せず、キー入力と左文脈を `rinzed` に送り、返ってきた表示指示（確定文字列・未確定文字列・候補一覧など）をそのまま描画する。
- **接続単位で入力状態を分離する**: `rinzed` はクライアント接続ごとに独立した入力状態を持つ。Neovim では挿入モード・[コマンドライン](../frontends/neovim-cmdline.md)・[blink.cmp](../frontends/neovim-blink.md) の問い合わせで接続を分け、fcitx5 や macOS では入力欄（入力コンテキスト）ごとに接続を分けることで、状態が混ざらないようにしている。
- **I/O から切り離した純粋な状態機械**: SKK の入力状態機械（`rinze-engine`）はファイルやモデルへの依存を持たず、外部とのやり取りを抽象トレイト（`Converter`）に委ねる。これにより、モデルなしでの単体テストやロジックの検証を容易にしている。

## クレート一覧

| クレート | 責務 |
| --- | --- |
| `rinze-engine` | SKK の入力状態機械。入力モード、ローマ字変換、▽ / ▼ の状態遷移、abbrev、候補選択、入れ子を含む辞書登録、候補削除の確認を担う。I/O を持たない |
| `rinze-dict` | SKK 辞書の読み込み・検索、およびユーザー辞書への登録・削除（`skk-ignore-dic-word` による除外を含む） |
| `rinze-zenz` | zenz モデルを用いた候補のスコアリングと、ビーム探索による表記生成 |
| `rinzed` | 常駐デーモン。システム辞書・ユーザー辞書・学習履歴・zenz を保持し、Unix ドメインソケット経由で msgpack-rpc を待ち受ける。上記の 3 クレートを統合し、ユーザー辞書と学習履歴への書き込みを一手に担う |
| `rinze-socket` | 既定ソケットパスの解決規則、ソケット所有者・接続元ユーザーの検証、メッセージサイズ・構造の境界検査。`rinzed` と `rinze-client` で共有する |
| `rinze-client` | ネイティブフロントエンド向けのクライアントライブラリ。`rinzed` への接続・自動起動、応答の解釈、左文脈の整形を担い、C ABI 経由で [fcitx5](../frontends/fcitx5.md) と [macOS](../frontends/macos.md) から利用する |

各フロントエンドの実装はリポジトリ直下の `nvim/`（Neovim）、`fcitx5/`（fcitx5）、`macos/`（macOS）に配置している。
