# 通信設計

フロントエンドと `rinzed` は、Unix ドメインソケット上の msgpack-rpc で通信する。
要求は接続ごとに到着順で直列処理し、フロントエンドが入力状態を推測しなくて済むよう、応答に描画と制御に必要な情報をすべて含める設計としている。

## 要求の種類

| メソッド | 役割 |
| --- | --- |
| `key(key, left_context)` | キー入力とカーソル直前の左文脈を送り、状態遷移と描画更新を得る |
| `flush()` | 入力途中の文字列を表示どおりに確定して状態を初期化する。入力モードは維持する |
| `discard()` | 入力途中の文字列を確定せずに破棄し、状態を初期化する。学習履歴には記録しない。フォーカス喪失時などに使う |
| `reset()` | `flush` を行ったうえで入力モードをひらがなに戻す。入力有効化時の初期化に使う |
| `choose(version, word, left_context)` | 見出し入力中（▽）に指定候補で直接確定する。状態バージョンが一致しない場合は無視し、非同期補完との競合を防ぐ |
| `lookup(reading, left_context)` | 送り仮名のない読みに対する変換候補と注釈の一覧を返す。入力状態を変更しないため、キー処理用の接続とは別接続で非同期に問い合わせられる |

## 応答の構造

`lookup` 以外の要求に対して、`rinzed` は以下の項目を含むマップを返す。

| キー | 意味 |
| --- | --- |
| `handled` | `false` の場合、フロントエンドは `commit` を挿入したうえで元のキーを通常の処理へフォールバックする |
| `commit` | 確定して入力先へ挿入する文字列 |
| `preedit` | 現在の未確定文字列（例: `▽あし`、`▼明日`） |
| `annotation` | インライン変換中に表示している候補の辞書注釈。候補一覧の表示中や注釈がない場合は nil |
| `candidates` | 候補一覧の表示中のみ含まれるページ情報と候補リスト（選択キー・語・辞書注釈）。通常時は nil |
| `minibuffer` | 辞書登録や候補削除の確認中のみ含まれる、最も内側のプロンプト・確定済み文字列・未確定文字列 |
| `mode` | 次のキーを受け取る階層の入力モード（`hiragana` / `katakana` / `halfwidth-katakana` / `ascii` / `fullwidth-latin`） |
| `passthrough` | `true` の間は `C-j` 以外のキーを処理しないことを示す。フロントエンドはこのフラグを見て不要な RPC 送信を省略できる |
| `reading` | 見出し入力中（▽）における変換対象の読み。送り仮名入力中や abbrev、辞書登録中は nil |
| `version` | 接続ごとに要求処理のたびに単調増加する番号。`choose` による非同期確定の整合性確認に使う |

## 状態管理とキャッシュ

- **入れ子状態の隠蔽**: 辞書登録が入れ子になっていても、`preedit` には元の位置の未確定文字列を、`minibuffer` には最も内側の入力欄を返す。入れ子スタックの管理はすべて `rinzed` 側で完結する。
- **切断時の扱い**: 接続が閉じられた場合、`rinzed` はその接続の未確定状態を確定せずに破棄し、学習履歴にも残さない。
- **スコアキャッシュ**: `rinzed` は直近の zenz スコアリング結果を保持しており、同じ左文脈・読み・候補の組み合わせであれば再計算を省く。これにより、入力中の先読み（[blink.cmp との連携](../frontends/neovim-blink.md)）と直後の Space 変換がシームレスにつながる。

## セキュリティ境界

- **同一ユーザー検証**: `rinzed` は接続を受け付けるたびに、OS の仕組みで接続元プロセスの所有者が自分と同じユーザーであることを検証する。クライアント側も接続前にソケットの所有者を検証する。
- **片方向通信の前提**: フロントエンドは `rinzed` からの要求（コールバック）を受け付けず、応答のみを解釈する。特に Neovim ではソケット経由でエディタ API を呼ばれない構成にしている。
- **リソース上限**: 同時接続数や 1 メッセージあたりのサイズ・入れ子深さには上限を設け、異常な入力や過剰な接続によるリソース枯渇を防ぐ。
